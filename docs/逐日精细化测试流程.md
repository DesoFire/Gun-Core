# 逐日精细化测试流程

本文档记录 Gun-Core demo 的逐日精细化测试方法。它用于观察一次“像玩家一样经营”的完整过程，而不是只看大量模拟后的平均值。

## 测试目标

逐日测试重点回答这些问题：

- 玩家每天实际做了什么：调查、接契约、招募、解雇、升级设施、买装备、治疗伤病、支付隐秘费用。
- 基地经济是否能滚动起来：资金、日支出、预付款、契约尾款、外勤补发工资、隐秘费用之间是否形成合理压力。
- 契约难度是否自然上升：基地声望提高后，契约战力需求、收益、风险是否同步变化。
- 佣兵是否会成为长期资产或负资产：压力、伤势、负面状态、个人声望、死亡风险是否给玩家制造取舍。
- 基础设施是否有存在感：情报室、黑市、医疗中心、兵营、防御设施是否会被测试策略主动使用，并改变后续决策。

## 脚本位置

逐日测试脚本：

```powershell
node tools\daily-audit-sim.mjs
```

脚本会重置一次新游戏，并把 Markdown 报告输出到标准输出。推荐重定向到 `reports` 目录：

```powershell
node tools\daily-audit-sim.mjs 45 growth daily-growth-001 > reports\daily-audit-growth.md
```

参数含义：

- 参数 1：模拟天数，默认 `45`。
- 参数 2：策略 ID，默认 `growth`。
- 参数 3：随机种子，默认根据策略生成。固定种子可以复现同一次测试。

## 可选策略

| 策略 ID | 中文含义 | 行为倾向 | 适合观察 |
| --- | --- | --- | --- |
| `conservative` | 保守调查型 | 接单前更重视调查和成功率，保留更多现金 | 调查成本、稳健玩法收益、低风险成长 |
| `aggressive` | 激进接单型 | 调查少，现金储备低，更愿意接高收益单 | 失败惩罚、伤亡压力、破产速度 |
| `growth` | 成长优先型 | 尽量维持 4 人队伍，兼顾调查、接单和设施 | 默认推荐，用于观察主线经营体验 |
| `profit` | 现金积累型 | 偏向单位时间收益，不主动消费财富目标 | 纯攒钱体验、经济正反馈强度 |

## 报告字段

报告开头是本轮总览：

- 起始/结束：展示本轮开局与结束时的基地状态。
- 行动统计：统计派遣、调查、招募、设施升级、黑市购买、医院治疗次数。
- 结果统计：统计完成契约、失败契约、死亡、新增状态。

每天都会记录以下内容：

- 日初基地：当天行动前的资金、基地声望、隐秘、遇袭率、未付声望、日支出、佣兵数量、战力、压力、伤势、设施。
- 契约面板：当天看到的可接契约，包含报酬、已知战力区间和截止日。
- 当日行动：脚本当天主动执行的所有经营操作。
- 推进结算：点击进入下一天后的净变化，包括资金、隐秘、基地声望、均压、均伤、完成/失败契约、死亡、状态变化。
- 日末基地：结算后的基地状态。
- 执行中契约：仍在外勤的契约和剩余天数。
- 佣兵状态：每名佣兵的评级、状态、战力、压力、伤势、个人声望、负面状态。
- 关键日志：当天系统日志中的重要结果，例如契约成功、负面状态、外勤薪资补发、每日支出。

## 推荐测试流程

1. 先跑默认成长策略 45 天：

```powershell
node tools\daily-audit-sim.mjs 45 growth daily-growth-001 > reports\daily-audit-growth.md
```

2. 再跑现金积累策略 45 天：

```powershell
node tools\daily-audit-sim.mjs 45 profit daily-profit-001 > reports\daily-audit-profit.md
```

3. 如果要压测失败和伤亡，跑激进策略：

```powershell
node tools\daily-audit-sim.mjs 45 aggressive daily-aggressive-001 > reports\daily-audit-aggressive.md
```

4. 如果发现某一天不合理，保留同一个种子和策略重复运行。只要代码和参数没有变化，同一个种子会复现相同过程。

## 平衡性阅读方法

建议优先看这些信号：

- 第 1 到 7 天：玩家是否能接到契约，是否过早卡死在调查费、招募费或日支出上。
- 第 8 到 20 天：资金是否开始稳定上涨，还是被工资、补给、维护和医疗长期吞掉。
- 第 21 天以后：基地声望提高后，契约收益是否足以覆盖更高风险、隐秘压力和伤病成本。
- 月初附近：隐秘费用是否形成明确压力，未支付声望是否会让隐秘下降过快。
- 设施升级日：升级设施之后，后续几天是否能看出实际收益。
- 佣兵状态：如果高压、重伤、负面状态快速堆满，说明伤病或压力曲线太陡；如果长期无伤无压，说明风险不足。

## 与批量测试的区别

`tools/balance-sim.mjs` 适合看多轮平均结果，例如平均资金、死亡率、完成率。

`tools/daily-audit-sim.mjs` 适合看单局过程细节，例如某一天为什么没钱、为什么接不了契约、某个佣兵为什么突然变成负资产。

推荐流程是先用逐日报告发现问题，再用批量测试确认修改后的整体趋势。
